## Introduction

NGINX is one of the most widely used high-performance web servers and reverse proxies in the world. It is exceptional at distributing traffic across multiple backend servers.

In this guide, we will set up a practical load balancing scenario using Docker Compose. We will spin up three separate Node.js backend servers and one NGINX instance configured to distribute traffic among them.

## Prerequisites

Ensure you have Docker and Docker Compose installed on your machine.

Create a new directory for this project:

```bash
mkdir nginx-load-balancer
cd nginx-load-balancer
```

## 1. Creating the Backend Service

First, let's create a simple Node.js backend server. It will respond to requests with a message indicating which server handled the request, making it easy to observe the load balancer in action.

Create a directory named `app` and inside it, create `package.json` and `server.js`.

**app/package.json**
```json
{
  "name": "backend-node",
  "version": "1.0.0",
  "main": "server.js",
  "dependencies": {
    "express": "^4.18.2"
  }
}
```

**app/server.js**
```javascript
const express = require('express');
const app = express();

// We will pass the server ID as an environment variable
const SERVER_ID = process.env.SERVER_ID || 'Unknown';
const PORT = 3000;

app.get('/', (req, res) => {
    console.log(`Request received by Server ${SERVER_ID}`);
    res.json({
        message: 'Request successful',
        servedBy: `Server ${SERVER_ID}`
    });
});

app.listen(PORT, () => {
    console.log(`Server ${SERVER_ID} listening on port ${PORT}`);
});
```

Create a `Dockerfile` inside the `app` directory to containerize this Node.js app:

**app/Dockerfile**
```dockerfile
FROM node:18-alpine
WORKDIR /usr/src/app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD [ "node", "server.js" ]
```

## 2. Configuring NGINX

Next, we need to configure NGINX. Create an `nginx.conf` file in the root of your project (outside the `app` folder).

**nginx.conf**
```nginx
events {}

http {
    # Define a group of backend servers
    upstream backend_servers {
        # By default, NGINX uses Round Robin
        server backend1:3000;
        server backend2:3000;
        server backend3:3000;
    }

    server {
        # Listen on port 80
        listen 80;

        location / {
            # Proxy all requests to the upstream group named 'backend_servers'
            proxy_pass http://backend_servers;
            
            # Forward important headers to the backend
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        }
    }
}
```

### Explanation of nginx.conf

1. **`upstream backend_servers`**: This block defines the cluster of servers that will handle the requests. We list three servers: `backend1`, `backend2`, and `backend3`. These names will be resolved by Docker's internal DNS network.
2. **`proxy_pass`**: Inside the `server` block, the `proxy_pass http://backend_servers;` directive tells NGINX to take any incoming request on port 80 and forward it to one of the servers defined in the `upstream` block.

## 3. Orchestrating with Docker Compose

Now, let's tie it all together using Docker Compose. Create a `docker-compose.yml` file in the root directory.

**docker-compose.yml**
```yaml
version: '3'
services:
  # The NGINX Load Balancer
  loadbalancer:
    image: nginx:latest
    ports:
      - "8080:80"
    volumes:
      - ./nginx.conf:/etc/nginx/nginx.conf:ro
    depends_on:
      - backend1
      - backend2
      - backend3

  # Backend Server 1
  backend1:
    build: ./app
    environment:
      - SERVER_ID=1

  # Backend Server 2
  backend2:
    build: ./app
    environment:
      - SERVER_ID=2

  # Backend Server 3
  backend3:
    build: ./app
    environment:
      - SERVER_ID=3
```

## 4. Running and Testing

Start the cluster by running:

```bash
docker-compose up --build
```

You will see logs from NGINX and all three backend servers spinning up.

Now, test the load balancer by sending requests to `http://localhost:8080`. You can use your browser or a tool like `curl`.

```bash
curl http://localhost:8080
```

**Expected Output:**

Run the `curl` command multiple times. Because NGINX defaults to the **Round Robin** algorithm, you should see the responses cycle perfectly through the servers:

1. `{"message":"Request successful","servedBy":"Server 1"}`
2. `{"message":"Request successful","servedBy":"Server 2"}`
3. `{"message":"Request successful","servedBy":"Server 3"}`
4. `{"message":"Request successful","servedBy":"Server 1"}`

## 5. Changing the Algorithm

To test a different algorithm, open `nginx.conf` and modify the `upstream` block.

### Least Connections

If you want NGINX to send requests to the server with the fewest active connections, add the `least_conn` directive:

```nginx
    upstream backend_servers {
        least_conn;
        server backend1:3000;
        server backend2:3000;
        server backend3:3000;
    }
```

### IP Hash

If you need session persistence (ensuring a specific user always hits the same backend server), use the `ip_hash` directive. It calculates a hash based on the client's IP address.

```nginx
    upstream backend_servers {
        ip_hash;
        server backend1:3000;
        server backend2:3000;
        server backend3:3000;
    }
```

After modifying `nginx.conf`, restart the NGINX container to apply the changes:

```bash
docker-compose restart loadbalancer
```

If you test with `ip_hash`, you will notice that repeated `curl` commands from your local machine will always be served by the exact same server (e.g., Server 2), because your IP address remains constant.
