## Defining and Using Structs

```rust
struct Person {
    name: String,
    age: u8,
}

fn describe(person: &Person) {
    println!("{} is {} years old", person.name, person.age);
}

let mut peter = Person {
    name: String::from("Peter"),
    age: 27,
};
describe(&peter);

peter.age = 28;
describe(&peter);
```

The function takes `&Person` (a reference), meaning it borrows the struct without taking ownership.

## Field Init Shorthand

When you have variables with the same name as the struct fields, you can use the shorthand:

```rust
let name = String::from("Jean");
let age = 39;
let jean = Person { name, age };
```

Instead of writing `name: name, age: age`.

## Struct Update Syntax

Create a new struct using values from an existing one:

```rust
let ned = Person {
    name: String::from("Ned"),
    ..jean
};
```

`..jean` copies the remaining fields from `jean`. It must always be the last element.

## Debug Trait

A custom struct doesn't implement the Debug trait on its own, so `println!("{ned:?}")` and `dbg!(ned)` would both fail to compile.

You can tell Rust to automatically implement Debug for your struct using `#[derive(Debug)]`:

```rust
#[derive(Debug)]
struct Animal {
    name: String,
    action: String,
    age: u8,
}

let dog = Animal {
    name: String::from("Fuggu"),
    action: String::from("bark"),
    age: 8,
};

dbg!(&dog);
println!("Dog: {dog:?}");
```

Both work now. The struct update syntax works here too:

```rust
let cat = Animal {
    name: String::from("Cat"),
    ..dog
};
println!("Cat: {cat:?}");
```

## Tuple Structs

If the field names are unimportant, you can use a tuple struct:

```rust
struct Point(i32, i32);

let p = Point(17, 23);
println!("({}, {})", p.0, p.1);
```

The major advantage over a plain tuple is type safety. `struct Point(i32, i32)` and `struct Size(i32, i32)` are different types even though both contain two `i32`s. Rust won't let you accidentally use a `Size` where a `Point` is expected.

They're also useful for wrapping a single value into a distinct type:

```rust
struct Celsius(f64);
struct Fahrenheit(f64);
```

`Celsius(25.0)` and `Fahrenheit(80.0)` are different types despite both internally containing an `f64`.

Think of a tuple struct as a lightweight way to create a new type without having to name each field.

## Zero-Sized Types

A zero-sized type (ZST) is a struct that contains no data but can still represent a type or provide some behavior.

```rust
struct NullReader;

let reader = NullReader;
```

Since it contains no data, there's nothing to distinguish between two instances like `let a = NullReader` and `let b = NullReader` -- both simply represent `NullReader`.

The usefulness comes from giving the type behavior:

```rust
impl NullReader {
    fn read(&self) {
        println!("EOF");
    }
}

reader.read();
```

A ZST is useful when you need a type to represent a concept or behavior rather than actual data.
