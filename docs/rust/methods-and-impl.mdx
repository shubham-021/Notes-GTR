## Impl Blocks

Rust lets you associate functions with your new types using an `impl` block:

```rust
#[derive(Debug)]
struct CarRace {
    name: String,
    laps: Vec<i32>,
}

impl CarRace {
    fn new(name: &str) -> Self {
        Self { name: String::from(name), laps: Vec::new() }
    }

    fn add_lap(&mut self, lap: i32) {
        self.laps.push(lap);
    }

    fn print_laps(&self) {
        println!("Recorded {} laps for {}:", self.laps.len(), self.name);
        for (idx, lap) in self.laps.iter().enumerate() {
            println!("Lap {idx}: {lap} sec");
        }
    }

    fn finish(self) {
        let total: i32 = self.laps.iter().sum();
        println!("Race {} is finished, total lap time: {}", self.name, total);
    }
}

let mut race = CarRace::new("Monaco Grand Prix");
race.add_lap(70);
race.add_lap(68);
race.print_laps();
race.add_lap(71);
race.print_laps();
race.finish();
// race.add_lap(42); // error: race has been moved
```

`self` means the particular instance of the type that the method was called on.

## Receiver Types

The `self` argument specifies the "receiver" -- the object the method acts on. There are several common receivers:

**`&self`** borrows the object using a shared and immutable reference. The object can be used again afterward.

**`&mut self`** borrows the object using a unique and mutable reference. The object can be used again afterward.

**`self`** takes ownership of the object and moves it away from the caller. The method becomes the owner. The object will be dropped (deallocated) when the method returns, unless its ownership is explicitly transmitted. Complete ownership does not automatically mean mutability.

**`mut self`** is the same as `self`, but the method can mutate the object.

**No receiver** makes it a static method on the struct. Typically used to create constructors, which are called `new` by convention.

In short:

- `self` → ownership
- `&self` → immutable borrow
- `&mut self` → mutable borrow

## iter() vs Direct Consumption

```rust
for lap in self.laps.iter() {
    println!("{lap}");
}
```

This borrows the elements. The vector remains yours, and you can keep using `self.laps` afterward.

```rust
for lap in self.laps {
    println!("{lap}");
}
```

This moves the vector's elements out. Afterward, you can't use `self.laps`. That's why in `print_laps(&self)`, you can't do `for lap in self.laps` -- because `self` is borrowed, and you're trying to move its `laps` out. You use `self.laps.iter()` instead, which just borrows the elements.

## enumerate()

`enumerate()` takes an iterator and attaches an index to each item:

```
70 → (0, 70)
68 → (1, 68)
71 → (2, 71)
```

That's why you can write:

```rust
for (idx, lap) in self.laps.iter().enumerate() {
    println!("Lap {idx}: {lap} sec");
}
```

You can't do `self.laps.enumerate()` because `Vec` is not an `Iterator`. A `Vec` is a collection containing values. An `Iterator` is a thing that knows how to produce values one at a time. `enumerate()` needs the second one.

Rust's `for` loop automatically converts many things into an iterator using `IntoIterator`. That's why `for lap in laps` works even though `laps` isn't technically an iterator. Roughly, Rust turns it into `for lap in laps.into_iter()`. When you explicitly write `self.laps.iter().enumerate()`, you're telling Rust exactly how you want to iterate: borrow the vector's elements, then attach indices.

## Common Iterator Methods

`vec.iter().sum()` creates an iterator over the vector's elements, then `sum()` consumes that iterator and adds the elements together, returning the total.

Other useful ones:

- `vec.iter().sum()` -- add everything
- `vec.iter().count()` -- number of elements
- `vec.iter().min()` -- smallest
- `vec.iter().max()` -- largest
- `vec.iter().any(...)` -- does at least one satisfy the condition?
- `vec.iter().all(...)` -- do all satisfy the condition?
- `vec.iter().find(...)` -- find first matching element
- `vec.iter().filter(...)` -- keep matching elements
- `vec.iter().map(...)` -- transform each element
- `vec.iter().enumerate()` -- add index

## Box and Smart Pointer Receivers

`Box<T>` is a Rust smart pointer that puts a value on the heap instead of storing it directly on the stack.

```rust
let car = Box::new(Car { ... });
```

Conceptually:

```
Stack             Heap
car (pointer) →   Car { ... }
```

`car` itself is not the `Car`; it is a `Box<Car>` that owns and points to the heap-allocated `Car`.

The thing before the method name doesn't have to be only `self`, `&self`, or `&mut self`. Rust also allows certain wrapper types around `Self` to act as the receiver:

```rust
impl Car {
    fn drive(self: Box<Self>) { ... }
}
```

Now the method must be called on a `Box<Car>`:

```rust
let car = Box::new(Car { ... });
car.drive();
```

The important distinction:

- `self` → method receives a `Car`
- `Box<Self>` → method receives a `Box<Car>`

`Self` here means the type being implemented, so inside `impl Car`, `Self = Car`.

Rust allows several special receiver forms:

- `self`
- `&self`
- `&mut self`
- `Box<Self>`
- `Rc<Self>`
- `Arc<Self>`

This is useful when you want the method to operate on the wrapper/ownership representation of the object rather than directly on the object itself.

## Multiple Impl Blocks

Rust doesn't require you to put everything related to a type into one `impl` block.

```rust
impl Dog {
    fn new(name: String) -> Self {
        Self { name }
    }
}

impl Dog {
    fn bark(&self) {
        println!("Woof!");
    }
}
```

Both blocks belong to `Dog`, so Rust treats them as if they were one collection of methods. You could put both in one block, but you don't have to. These `impl` blocks can even be placed in different modules or files.
