## Functions and Return Values

```rust
fn fib(n: u32) -> u32 {
    if n <= 0 {
        println!("Invalid input");
        return 0;
    }

    if n <= 2 {
        n - 1
    } else {
        fib(n - 1) + fib(n - 2)
    }
}
```

The last expression in a function body (or any block) becomes the return value. Simply omit the `;` at the end of the expression. The `return` keyword can be used for early return, but the "bare value" form is idiomatic at the end of a function.

## Expression vs Statement

This is a subtle but important distinction. Consider this version of fib:

```rust
fn fib(n: u32) -> u32 {
    if n <= 2 {
        n - 1
    }

    fib(n - 1) + fib(n - 2)
}
```

The `if` block here doesn't return the value `n - 1` from the function. `n - 1` is the value of the `if` block, but that value is immediately discarded because the `if` itself isn't being used as the function's final expression. The function's last expression is the recursive call, so it always runs regardless of the condition.

Compare with:

```rust
fn fib(n: u32) -> u32 {
    if n <= 2 {
        n - 1
    } else {
        fib(n - 1) + fib(n - 2)
    }
}
```

Here the entire `if`/`else` is the last expression of the function, so its value becomes the function's return value.

## Another Example

```rust
fn gcd(a: u32, b: u32) -> u32 {
    if b > 0 { gcd(b, a % b) } else { a }
}
```

The whole `if`/`else` is the final expression, so whichever branch matches, its value is returned.

## Panic

In Rust, panic means the program encountered an unrecoverable error and stopped normal execution. When something panics, the thread's stack unwinds and the program (or thread) terminates.

## assert!

Used to say: "this condition must be true."

```rust
let x = 10;
assert!(x > 5);
```

Nothing happens if the condition is true. But:

```rust
assert!(x < 5);
```

This causes the program to panic:

```
thread 'main' panicked at ...
assertion failed: x < 5
```

You can provide a custom message:

```rust
assert!(x < 5, "x should be less than 5");
```

It's mainly used when you're checking that something that must be true actually is true.

There are also `assert_eq!` and `assert_ne!`:

```rust
assert_eq!(4, 2 + 2);
assert_ne!(prime % i, 0);
```

`assert_eq!` checks two values are equal. `assert_ne!` checks they are not equal. If the assertion fails, the program panics.

## unreachable!

This means: "the program should never reach this point."

```rust
match x {
    1 => println!("one"),
    2 => println!("two"),
    _ => unreachable!(),
}
```

If somehow the `_` case happens, Rust panics. You can explain why:

```rust
_ => unreachable!("x can only be 1 or 2"),
```

It's useful when your program's logic guarantees that a piece of code should never execute.

## eprintln!

This is the stderr version of `println!`:

- `println!()` writes to stdout
- `eprintln!()` writes to stderr

```rust
println!("normal output");
eprintln!("error/debug output");
```

The user sees both in the terminal, but they go to different streams. This becomes useful when redirecting output:

```bash
cargo run > output.txt
```

The `println!()` output goes into `output.txt`, while `eprintln!()` still appears in the terminal.

## const fn

A `const fn` is a function that can be evaluated at compile time.

```rust
const DIGEST_SIZE: usize = 3;
const FILL_VALUE: u8 = calculate_fill_value();

const fn calculate_fill_value() -> u8 {
    if DIGEST_SIZE < 10 { 42 } else { 13 }
}
```

Because `FILL_VALUE` is a `const`, Rust must calculate its value at compile time. If you declared `calculate_fill_value` as an ordinary `fn`, Rust would reject the call because ordinary functions cannot be called in const expressions. Marking it `const fn` tells Rust: "this function is safe to run at compile time."

## Exercise: Collatz Sequence

The Collatz Sequence is defined as follows, for an arbitrary n1 greater than zero:

- If ni is 1, then the sequence terminates at ni.
- If ni is even, then ni+1 = ni / 2.
- If ni is odd, then ni+1 = 3 * ni + 1.

For example, beginning with n1 = 3:

```
3 is odd, so n2 = 3 * 3 + 1 = 10
10 is even, so n3 = 10 / 2 = 5
5 is odd, so n4 = 3 * 5 + 1 = 16
16 is even, so n5 = 16 / 2 = 8
8 is even, so n6 = 8 / 2 = 4
4 is even, so n7 = 4 / 2 = 2
2 is even, so n8 = 1
the sequence terminates.
```

Write a function to calculate the length of the Collatz sequence for a given initial n.
